## Actual checked results and proof attempt

`m4/Codec.v` proves body execution, function call and Clight small-step results
for actual generated `get32`/`get64`, with arbitrary readable initialized byte
values, block/offset, program and call continuation. The owned variants forbid
address-space wrap. The results use exact unsigned shift/OR reconstruction,
unchanged memory and an empty trace. Allocated-and-written buffers inhabit the
4/8-byte ownership premises. Additional facts place both functions in the actual
generated program definitions. These are terminating legal executions of the
pure readers, not universal safety of the effectful framing/helper program.

The reporting proof attempt reaches the real `write_all` write call.
`m4/Attempt.v` retains the complete arbitrary-owned-byte return-bound goal, prints
the remaining obligation, and aborts it. It exports no completed theorem for that
goal. `external_functions_sem` is abstract: the stock axioms do not supply write
bounds, an owned/stable errno cell, transferred bytes, read results or progress.
The attempted call is checked by an exact equation against the generated AST.

`m4/Effects.v` supplies checked refutations of two concrete adapter choices:

- A silent external write relation admitting distinct short counts conflicts
  with CompCert `ec_determ`.
- A count-only read event cannot admit different byte contents for the same
  call/count/trace, because `ec_determ` forces equal resulting memories.
  Allocated memories with different initialized bytes inhabit this obstruction.
- The actual first `write_all` step has empty trace; bare Clight has no initial
  asynchronous process-loss edge.

These refute those adapters, not every possible CompCert/Clight route. They are
not substituted for the intended universal simulation. The independent effect
model proves transfer bounds, complete-consumption arithmetic and witnesses for
short/EINTR/error/loss/unbounded interruption prefixes; its connection to the C
loop remains unproved.

## Statements, assumptions and Lean edge

The additive `assurance/m4-claims.json` contains every authored Rocq theorem's
full type and transitive assumptions and 12 live-queried M2/M3 target types/axioms.
Kernel replay uses `coqchk`. The Rocq dependency union includes classical excluded
middle, dependent functional extensionality, constructive-real decision principles
`sig_not_dec`/`sig_forall_dec`, and external/inline-assembly semantics parameters
in semantic propositions. No claim treats these as Lean's foundations or as a
checked translation into Lean. No new authored axiom or admitted security theorem
supports the results.

The exact Lean targets include `LeanCageM3.decodeResult`, `resultValid`,
`decodeResult_valid`, `observe`, `private_report_knowledge`,
`report_loss_preserves_entry`, `cancel_not_completion`, `release_requires_extinction`,
`entry_requires_receipts`, `reachable_entry_ordered`, and M2's
`lost_report_unknown`/`entry_requires_plan`. Their original axioms/types are queried
rather than inferred from names. Intermediate native events include ADMITTED and
ENTERED; Lean's public final decoder rejects those tags and accepts different final
fields. An unchecked decoder equality would be false. Ordered event assembly and
final publication need separate relations. **No machine-checked Lean bridge exists.**

## Route decision and next work

Retain Clight for sequential C reasoning; reject the direct silent/count-only
adapter. Follow [§AR-m4-native.revision](../architecture/AR-m4-native.md#revision-byte-aware-effects-and-loss-before-the-lean-bridge): supply byte-aware effects or a checked
oracle observation relation, validate their interaction with CompCert's trace/
external-call properties, and add process loss at every source boundary. Changing
upstream event semantics invalidates automatic reuse of compiler theorems.
Then reattempt the selected full-slice simulation and memory safety before the
checked Lean connection. Preserve partial result mutation on rejected frames,
report failure, blocked calls, EOF, repeated interruption and asynchronous death.

[§RM-roadmap.m4.packages](../roadmap.md#m4packages-correspondence-work-after-the-reviewed-m3-baseline) updates M4.2–M4.6 accordingly. Linux enforcement, GCC/compiler/linker/loader,
Lean/native runtimes, deployed artifacts and all M5 hardware channels remain open.
