# Actual main policy-bound validation: claim review

This package follows [§AR-m4-controller.bounds](../architecture/AR-m4-controller.md#bounds-actual-policy-bound-validation) and [§DA-m4-controller.bounds](../decisions/architectural/DA-m4-controller.md#bounds-check-the-real-short-circuit-sequence) from
numeric-block checkpoint `65dba9c9fc2641b8ff1b80314e2bf614cd994d70`. It retains the
unchanged native helper, live Lean policy/encoder, pinned tools and every earlier
compiled identity. The review applies [§REQ-proof-integrity.statement](../requirements/REQ-proof-integrity.md#statement-review-the-proposition) to the
complete propositions and their transitive foundations.

The selected actual `main` statements contain the initial argument-count/byte
condition, nineteen short-circuit numeric guards and the final rejection branch.
`bounds_exact_structure` proves descriptor assembly equal to that actual AST.
A compiled negative mutation changes the memory upper bound and must fail this
identity; the checker does not trust a parallel handwritten source listing.

`bounds_region_source` constructs actual Clight steps from independent premises:
signed argument count 17 through INT_MAX, unsigned byte total, readable policy
cells, the actual global binding and the two initial temporary values. It does
not assume that the policy is valid or that a successful execution exists. The
word proofs cover signed subtraction, mixed integer/unsigned-long comparison,
the long CPU constant, modulus and boolean casts. The descriptor order matches
all nineteen source conditions. `guard_skipped` requires only the existing true
flag, so its two-step path needs no policy read or permission premise.

The source paths preserve arbitrary caller continuations. Acceptance stops at
`Sskip` after this selected block; rejection stops before its first `result_of`
call. The following environment lookup, reporting behavior and function return
are outside the claim. The complete block takes at most 140 source transitions.
Every actual prefix whose length is within the constructed path preserves the
entire memory; live prefixes have a next source step, and live executions of the
exact path length reach the prescribed endpoint. Loss exists at every boundary,
including the endpoint. No statement bounds arbitrary execution of subsequent
code or assumes that asynchronous loss cannot occur.

`complete_numeric_image` derives the readable policy image from the preceding
actual successful numeric stores. It is a memory connection; the intervening
parent, export, digest, executable and argument-length code has not been erased
or assumed to run successfully. The selected block is sequential and has no
concurrent memory-writer transition. Its ownership premises and the absence of
such a writer still need a whole-controller and Linux argument.

Nonvacuity starts from the actual complete translated program's constructible
initial memory. Actual scalar stores populate the policy global, retaining their
memory relation and its readable cells. The temporary environment is constructed
for this selected block, without claiming reachability from function entry.
Twenty-six witnesses comprise three accepted cases and twenty-three rejected
cases. They cover minimal/maximal limits, argument count and byte boundaries,
the first rejected guard at each of the nineteen positions, UINT64_MAX and
INT_MAX. The accepted zero-byte-total case deliberately exposes the block's local
scope: per-string checks and accumulation remain required earlier in the source.
These are kernel-constructed paths, not native or VM measurements.

The Lean interface `nativeBounds` checks argument count/bytes and the exact
numeric predicate over ten fields. `limits_exact` relates that predicate to the
live `limitsValid`, with the unencoded CPU period kept explicit. Live `argvValid`
and `planArgs` determine the corresponding argument count and UTF-8 byte total.
This does not certify Linux-supplied argument pointers or the native accumulation
loop. `pageRemainder_exact` proves the normalized structural remainder equal to
ordinary `Nat.mod` when its explicit fuel covers the input. No desired remainder,
alignment or policy validity is a premise of the source connection.

The direct standard-modulus export and then the ten-element sparse-pattern
export pulled in division/modulus proof dependencies. Their strict imports were
rejected at an `Iff` elimination path; the rejected artifacts/logs remain
recorded. Explicit field lookup/count and the proved structural remainder remove
that unsupported computational dependency without changing the policy contract
or disabling kernel checks. The final computational closure has 179 entries and
no exported axioms. The separate Lean equivalence proofs remain kernel checked
and included in the theorem audit.

`bounds_imported_execution` proves that this strictly imported interface selects
the same actual native endpoint, unchanged memory, finite live-prefix progress
and every-boundary loss. It retains the importer's existing definitional-UIP
model and translation-faithfulness obligation. Both proof-assistant endpoints
being checked does not prove the importer's translation faithful.

`python3 m4/policy/check.py` inventories all 64 Rocq and 36 Lean theorem records,
the imported computational endpoint, fifteen compiled identities and all export
entries. It checks complete types/foundations, parent source/header/artifact
identities, twelve integrity regressions, both compiled negative checks and an
independent kernel replay. Every earlier theorem, artifact, pin and raw receipt
remains preserved. Only named documentation and transitive evidence fingerprints
are amended explicitly; no expectation is refreshed to suppress a failure.

All sixteen original native/Linux ledger entries remain open. Physical argument
provenance, entry reachability, remaining input validation, actual accumulation,
reporting after rejection, setup/supervision/cleanup, the executable/runtime chain
and hardware channels still require their own connections. This advances the
bounded M4.3 controller work and does not complete M4.
