# AR-m4-parent: Trace-connected numeric, parent and initialization region

This bounded composition advances the controller edge of
[§FS-assurance.native](../functional-spec/FS-assurance.md#native-partial-m4-reporting-source-evidence) and the input checks of [§FS-workspace.policy](../functional-spec/FS-workspace.md#policy-bounded-typed-request). Its producer
is the owned numeric/argument memory contract; its consumers are the existing
initialization, argument and policy-bound source certificates. It advances
`M4-controller`, `M4-supervisor` and `M4-m3-policy` without closing those entries.

## history: Selected execution history

Execute the unchanged complete-helper region from numeric field initialization
through the existing post-policy-bounds frontier. Quantify over every local
machine transition, including arbitrary signed parent observations, conforming
string-library results, waits and process loss. Export the selected prefix of
the very execution being classified and its parent observations. Numeric or
parent-guard rejection has no parent observation. After the observation, retain
its actual value on mismatch and admission. Initialization is reachable only
after exactly one observation whose signed value equals the parsed positive
parent, at most `INT_MAX`. Later behavior beyond the selected endpoint inherits
no identity, memory or progress assertion from this region.

Memory changes are sequential. Earlier numeric stores and each executed flag or
pointer store survive subsequent rejection or loss. Prospective stores do not
assert execution. Non-wait source-step bounds are derived from the source
certificates, independently of the exhibited trace; waits give neither a time
bound nor unconditional termination.

## inputs: Owned input representation

Allocated executions must return the owned strings and selected argument-table
entries in the exact initial memory used by the execution. Return numeric input
mappings and all parent/export/digest/guest byte equalities, rather than only an
unrelated byte list. Universal contracts retain every alias permitted by their
stated ownership/separation premises. Fresh allocation witnesses may use stronger
separation. None of these results proves physical Linux process argv provenance.

## cases: Composition and interference evidence

Construct allocated complete-region acceptance and first-rejection executions:
early and late numeric failures, malformed/zero/overflow/out-of-range parents,
actual differing parent observations, and export/digest/executable/argument/bounds
failures in source order. Check exact endpoint and memory, including retained
earlier stores. Include loss before/after numeric writes, parent parsing and
observation, and each initialization write region; preserve waiting boundaries.
Compiled controls must reject changes to the actual parent guard, narrowing and
comparison while accepting unchanged source.

## audit: Maintained evidence and preserved candidate

Maintain a separate package and full declaration/type/transitive-foundation and
artifact inventory. Inventory every proof declaration in the checked environment
or reject unsupported source commands explicitly, including qualified/attributed
commands and proof-valued definitions. Regress missing declarations, changed
foundations/artifacts/exports, fabricated history, erased representation and
tampered receipts. The ordinary gate compares reviewed expectations and never
collects new expectations automatically.

Preserve `m4/parent-checkpoint/` and its snapshot and replay it at its original
revision. Documentation/dependency amendments must be enumerated and reviewed;
preserve prior statement, assumption, export and compiled artifact identities.
Acceptance requires a statement review and complete focused/aggregate replay.
It is a local Rocq source result; [§REQ-proof-integrity.kernel](../requirements/REQ-proof-integrity.md#kernel-kernel-checked-evidence) still requires an
ordinary Lean connection before it can support a sandbox security claim.

Physical argv, persistent parent identity, libc/Linux effects, concurrent writer
exclusion, compiler-semantics compatibility, linking/loader/runtime and the
importer's semantic faithfulness remain connecting obligations. Hardware-channel
confidentiality remains M5.
