# Parent validation review checkpoint

This is a **candidate for independent review**, frozen when the user requested
a break. It extends the remaining composition work in
[§AR-m4-controller.composition](../../docs/architecture/AR-m4-controller.md#composition-remaining-controller-obligations). The accepted baseline is initialization commit
`2db87b46d861ffd1c10e295a985818197b8c6170`; its claims, evidence and maintained gate
are unchanged. This directory is not an accepted extension of that claim ledger.

The candidate proposes the following bounded contract before promotion:

- Execute actual `number(argv[12], &parent)` at main suffix 15, including parser
  failure, zero, unsigned overflow and values above `INT_MAX`. Retain the actual
  first rejecting `result_of` call with setup/stage 1/ECHILD/entered 0.
- Reach `getppid` only after those short-circuit guards pass. Its local effect
  contract permits every signed 32-bit observation, arbitrary waiting and
  terminal process loss, with memory unchanged by the observation. Admission
  requires equality with the parsed positive parent value. No persistent parent
  identity or liveness is promised.
- Lift preceding regions to that extended machine and connect the actual numeric
  block, parent check and export-to-bounds initialization in source order. Keep
  earlier numeric and configuration writes on later rejection or loss. Preserve
  explicit ownership, separation, register and memory frames.
- Construct premises from full-program initial memory and allocated inputs.
  Selected argument cells begin at index 2; this is not physical argv provenance,
  allocation by main, or a proof starting at main entry. The general composition
  retains numeric/parent failures; the separate matching witness deliberately
  assumes successful parsing and a matching observation to exhibit a path.

This local `getppid` specification does not establish libc/Linux behavior.
Parent exit and reparenting remain possible. Later `pidfd_open`, repeated parent
checks, `PDEATHSIG`, arming, setup, supervision and cleanup remain separate.
The original sixteen obligations remain open; full M4 remains incomplete.

The source is original Apache-2.0 proof work using the existing pinned imports.
See [provenance](LICENSES.md) and the
[handoff and review priorities](../../docs/reviews/M4-checkpoint-handoff.md).

## Replay

From the repository root, after replaying the existing M4 dependency chain:

```sh
./scripts/check.sh
python3 m4/initialization/check.py
python3 m4/parent-checkpoint/verify.py
```

The last command rebuilds all 35 Rocq modules and the Lean module in a separate
ignored directory, independently checks the Rocq artifacts, extracts complete
theorem types and transitive foundations, validates the preserved baseline and
both strict export identities, and compares with the frozen candidate archive.
It does not approve the statements or update an accepted manifest. `--collect`
writes only an ignored report for review; it never refreshes the tracked archive.
Run it alone only when the baseline artifacts have already been built. See the
handoff for the complete dependency replay order on a fresh checkout.

The two exports are distinct: the caller-string closure has 161 entries; the
numeric plan parser closure has 173. Both are reused without modification.
No new strict import is generated by this candidate.

Candidate checking is evidence of kernel acceptance and source identity.
Statement review, whole-composition concrete cases, dedicated compiled negative
controls and integration into the maintained claim gate remain follow-up work
under [§REQ-proof-integrity.statement](../../docs/requirements/REQ-proof-integrity.md#statement-review-the-proposition). Counts are inventories, not security scores.
