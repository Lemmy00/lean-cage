# Actual native policy-bound validation

This package implements [§AR-m4-controller.bounds](../../docs/architecture/AR-m4-controller.md#bounds-actual-policy-bound-validation) against the complete unchanged
helper translation preserved by `m4/main`. It connects the nineteen numeric
guards, argument-count/byte checks and short-circuit order to actual source
steps. Both endpoints have a 140-step bound; all selected prefixes preserve the
entire memory, including loss at every boundary. Successful earlier numeric
stores establish the readable policy image.

The Lean interface is proved equivalent to live `limitsValid`, with the omitted
CPU period separate. Explicit field lookup/count and a proved page remainder
keep its computational export within the existing strict import profile. Its
imported result determines the native block's exact acceptance/rejection path.
The earlier modulus/sparse-pattern import attempts remain recorded experiments.

Run the parent replays, then:

```sh
python3 m4/policy/check.py
```

The gate checks complete statements and transitive foundations in both proof
assistants, strict import, a deliberately rejected descriptor mutation, the
independent kernel replay and integrity regressions. `--collect` writes ignored
candidate output only; reviewed manifests are never refreshed automatically.
The review is `docs/reviews/M4-policy-bounds.md`.

Twenty-six allocated source witnesses include three accepted vectors and
rejection at every numeric guard, count/byte overflows and machine extremes.
The zero-total-byte witness illustrates this block's local scope; earlier
per-string checks are still required. These are kernel-constructed source paths,
not VM measurements or proofs of reachability through all preceding checks.
Parent identity, digest/export/allowlist and accumulation code, reporting after
rejection, later setup/supervision, Linux, executable correspondence and hardware
channels remain separate obligations. This package does not complete M4.
